## 一、三步跑起来

> **板子还没买？完全不影响开工。**
>
> - **想看灯真的动** → VS Code 装 **Wokwi for VS Code** 扩展，`Ctrl+Shift+B` 编译，
>   再 `F1` → `Wokwi: Start Simulator`。一次性配置见 **`wokwi/README.md`**
>   （`wokwi.toml` 和 `diagram.json` 已经放在本目录，电路也连好了）
> - **想查语法有没有错** → 点"验证"编译**不需要插板子**，下面第 1 步的第 3 小步现在就能做
>
> 第 2 步以后是"板子到了之后"的流程。

**第 1 步 · 确认环境**

1. 用 Arduino IDE 2.x 打开本文件夹里的 `TrafficLight.ino`
   （注意：Arduino 要求**文件夹名和主 .ino 文件名一致**，所以不要重命名文件夹）
2. 工具 → 开发板 → `Arduino Uno`；工具 → 端口 → 选你板子对应的 `COMx`
   （**没有板子时这一栏是空的，直接跳过**；**有板子但端口那栏是灰的** → 先看指导文档 §1.2.1——很可能是兼容板缺 **CH340 驱动**，不是你的操作问题）
3. 点"验证"（编译）。**这一步不需要插板子**，而且必须零错误、零警告
4. 点"上传"，然后打开串口监视器（波特率 **9600**）

**第 2 步 · 看它自己证明自己没问题**

上传成功后，串口里应该依次出现：

```
==================================================
 Smart Traffic Light   skeleton vs0.0
 Hardware: Arduino Uno   guide: Lab 1
==================================================
 All tasks are TODO. See the module files.
[selftest] lighting 6 LEDs in order: NS R/Y/G -> EW R/Y/G
[selftest] done. LED dark or wrong order? check wiring first
[i2c] scanning bus ...
[i2c] found device 0x27
[i2c] total 1 device(s)
[display] LCD disabled (USE_LCD1602 = 0 in pins.h), serial only
[boot] ready. Start with the TODO in phases.cpp
```

同时六个灯会**依次各亮 0.5 秒**。这就是硬件自检（`phasesSelfTest`）——它会告诉你
接线和下载链路是否正常。**看到这一步，环境就算通了，之后所有问题都是代码问题。**

**第 3 步 · 开始写任务代码**

现在屏幕上什么都没有、灯也不循环，这是**正常的**——五个 TODO 都还没写。
按下面的清单逐个填。

### 冻结的三个接口

这三个签名是甲和乙之间的合同，**改之前必须通知对方**：

```c
float trafficflowQueueCm();                  // 乙 提供 → 甲 用它取排队长度
float readDistanceCM();                      // 乙 内部实现
unsigned long calcGreenTime(float queueCm);  // 甲 提供 → 返回该方向的绿灯时长
```

这条链路就是"两人可以整天不说话、各自推进"的全部秘密：
**乙只管把距离测准，甲只管把距离映射成时长。**

## 五、`USE_LCD1602` 这个开关是干什么的

`LCD` 依赖第三方库 `LiquidCrystal I2C`。为了让你**第 1 步就能编译成功**，
`pins.h` 里留了一个开关：

```c
#define USE_LCD1602    0    // ← 装好库之后改成 1
```

- `= 0`：不依赖任何第三方库，只用串口输出。**这是默认值，也是你的起跑线。**
- `= 1`：LCD 真正工作。装库步骤见指导文档 §1.2.2；`i2cScan()` 会帮你确认
  转接板地址到底是 `0x27` 还是 `0x3F`，**不要盲猜**。

## 六、协作约定（简版）

- **分支**：`main` 随时可编译可演示；开发一律开 `feat/xxx` 短分支。
- **同步**：每天早上 `git switch main && git pull`，再回到自己分支 `git merge main`。
  **别攒三天。同步频率和冲突面积成反比。**
- **合并**：走 PR + Squash merge；合并后打 tag（`v0.1-任务一完成` …）。
- **三条硬门槛**（PR 模板里会再问你一遍）：
  1. 能编译
  2. 跑过并贴了证据（串口日志 / 截图）
  3. **没有新增 `delay()`**
- **评审死锁的处理**：PR 提出后超过 12 小时无人响应，可自行合并并在群里说明。
  规则是为了让事情往前走，不是为了让流程好看。
- **不要提交**：编译产物、录屏、报告 PDF、原理图导出图（`.gitignore` 已经拦了大部分）。

## 七、出问题了先看这里

| 症状 | 先查什么 |
| --- | --- |
| 工具→端口是灰的 | ① USB 线可能只有电源线 ② **兼容板缺 CH340 驱动**（见指导文档 §1.2.1） |
| 串口全是乱码 | 串口监视器波特率不是 9600 |
| 点了"验证"但现象没变 | 忘了点"上传"——只编译不会下载进板子 |
| 上传报 `programmer is not responding` | 有外设接在 D0/D1 上了；或串口监视器还开着 |
| 编译报找不到 `LiquidCrystal_I2C.h` | 你还没装库 → 把 `pins.h` 里的 `USE_LCD1602` 改回 `0` |
| LCD 背光亮但没字 | 看串口里的 I2C 扫描结果改地址；再拧转接板上的蓝色电位器调对比度 |
| 灯完全不亮 | 先看 `[selftest]` 阶段有没有依次亮过；没亮就是接线/极性/下载链路问题 |
| 现象全对但串口刷屏卡住 | 你的 `displayUpdate()` 没做节流，9600 波特率发不完（见该文件 TODO） |
| 改了 `pins.h` 之后对方代码坏了 | 你违反了公告制 —— 下次先说一声 |

完整的排错表在指导文档**附录 B（25 条）**，那里更全。

> **第一次上手，请务必先读指导文档的「§ 0 零基础必读：六个硬件常识」。**
> 那一节是专为"会写程序但没碰过硬件"的同学写的——电平、LED 限流电阻、面包板、
> 编译与烧录的区别、串口、PWM，六个概念看懂了再动手，能省你至少两天的困惑。
>
> 另外，做完之后用指导文档的**附录 D 全项目验收自检表**逐条打勾，
